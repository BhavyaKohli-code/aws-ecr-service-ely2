This is the ELY agent, based on a project generated by the AgentCore CLI.

# Layout

The application code lives at the agent root directory. The `agentcore/` folder at the repo root holds the
configuration and state for this project. `agentcore deploy`, `dev`, and `invoke` rely on it.

## Agent Root

`main.py` is the entrypoint. The AgentCore SDK `@app.entrypoint` decorator defines a Starlette ASGI app that runs
a Strands agent and streams its events back to the caller.

- `model/load.py` — Bedrock model (`BEDROCK_MODEL_ID` env var)
- `mcp_client/client.py` — MCP client for the ELY AgentCore Gateway (`GATEWAY_URL` env var)
- `memory/session.py` — AgentCore Memory session manager (`MEMORY_ELYMEMORY_ID`, set by deploy)

## Auth flow

1. The caller invokes the runtime with a Cognito access token (`Authorization: Bearer <token>`).
2. Runtime validates it (`CUSTOM_JWT` authorizer in `agentcore/agentcore.json`) and forwards the header to the agent
   (`requestHeaderAllowlist: ["Authorization"]`).
3. The agent sends that same token to the Gateway on every MCP request.

## Request body

```json
{"prompt": "What is the leave policy?"}
```

`{"query": ...}` is also accepted for older callers. The response is a stream of Strands events (SSE).

## Environment Variables

| Variable | Required | Description |
| --- | --- | --- |
| `GATEWAY_URL` | No | ELY Gateway MCP endpoint (set in `agentcore.json`) |
| `BEDROCK_MODEL_ID` | No | Bedrock model or inference profile ID (set in `agentcore.json`) |
| `LOCAL_DEV` | No | Set to `1` to use `.env.local` instead of AgentCore Identity |

# Developing locally

`agentcore dev` starts a local server on 0.0.0.0:8080. In a new terminal:

`agentcore invoke --dev "What is the leave policy?"`

Locally there is no Runtime in front of the agent, so pass a Cognito token yourself if the Gateway needs one.

# Deployment

After providing AWS credentials, `agentcore deploy` deploys the project to Amazon Bedrock AgentCore.
Use `agentcore invoke` to invoke the deployed agent.
